# ADR 0001: Rust for all native code

Status: Accepted

## Context

Snapline needs low idle memory and CPU, direct access to Win32, WinRT, Direct2D and the Windows Credential Manager, and one build that ships as a small Windows binary. The product is Windows-first, GPLv3-or-later, and intends to add a separate Linux build later.

## Decision

All native code is Rust on the stable MSVC target. The three crates that hold rules and data, `snapline-core`, `snapline-store` and `snapline-upload`, forbid unsafe code. Win32 and WinRT calls live in `snapline-win` and `snapline-overlay`. The application layer, `snapline-services`, does not depend on the UI toolkit.

## Consequences

The team needs Rust skills and a Visual Studio Build Tools linker. A single language covers the tray, hotkeys, capture, annotation, uploads and recording. Unsafe code is isolated to two crates, each call wrapped by a safe function with a SAFETY line. The Linux build reuses the four portable crates unchanged.
